# agent-iron-rules

> Agent 操作铁律 —— 通用思考规则，在任何任务中强制生效。定义"怎么做才是对的"。

## 基本信息

| 字段 | 值 |
|------|-----|
| **名称** | `agent-iron-rules` |
| **类型** | 强制预加载型 skill（通用，不加载 = 无规则裸跑） |
| **标签** | `操作铁律` `范围控制` `危险操作` `沟通规则` `Karpathy` `四原则` `硬约束` `通用` |

## 简介

agent-iron-rules 是 Agent 的**通用思考规则**，不是毕业设计专用——在任何任务中强制生效。

在毕业设计场景中，与 `grad-design-squad` 并列加载（grad-design-squad 定义"谁做什么、怎么协调"，agent-iron-rules 定义"怎么做才是对的"）。在非毕业设计场景中，独立加载——任何涉及文件修改、代码编辑、内容创作的任务都应建立操作边界。

### 六大节铁律

**一、范围控制**
- 只改该改的——禁止顺手重构、重命名、优化无关代码
- 大改前先确认——显著改动必须停下等用户确认
- 改完列清单——改动文件、有意未动、需跟进

**二、危险操作确认**
- 破坏性操作（删除文件/覆盖代码/删数据库记录）→ 必须先列受影响内容
- 高危操作（部署/推送/数据库迁移/发邮件/外部API）→ 必须当次会话明确确认
- 替我操作先问——禁止替用户发送/发布/分享任何东西

**三、沟通规则**
- 拒绝废话开场——直接从答案本身开始
- 先给选项——重要任务先给 2-3 个方案，每个一句话说明取舍
- 不确定就直说——"我对这点不确定"比假装知道好
- 篇幅看需求——简单直接简短，复杂完整详尽

**四、记忆与背景**
- 维护 MEMORY.md（决定 + 原因 + 否决项）
- 维护 ERRORS.md（失败方法 + 成功方法 + 注意事项）
- 立永久铁律——始终成立的事实，有冲突先提出来

**五、核心原则（Karpathy 四原则）**
1. 要问，别假设——绝不对意图、架构、需求想当然
2. 先用最简单方案——能跑通就行，不加没要求的抽象
3. 别碰无关代码——不属于当前任务的，哪怕能改进也不动
4. 明确标注不确定——没把握就先说

**六、与 Agent Team 架构的集成约束**（毕业设计场景专属）
- 用户决策检查点：Squad Plan 阶段 → 给 2-3 方案 → 等用户选定 → 才生成 task_plan
- 危险操作门禁：Level-2（破坏性）/ Level-3（高危）→ 暂停获确认
- 改动清单协议：verification_report.md 必须含三部分

### 附带协议

- **工作流运行报告协议**：播报格式 [中文名] 步骤编号 | 阶段 | 进度，每 30s 至少一次
- **进度播报铁律**：不重复、遇阻塞立即报、完成后播总结

## 触发方式

### 毕业设计场景
任何毕业设计关键词触发 `grad-design-squad` 时，本 skill **同时自动激活**。

### 非毕业设计场景
AGENTS.md 中定义的非毕业设计触发词直接触发本 skill 独立加载——任何涉及文件修改、代码编辑的工作都应受铁律约束。

## 安装

将整个 `agent-iron-rules` 文件夹复制到 `%CODEX_HOME%\skills\` 下：

```
C:\Users\<用户名>\.codex\skills\agent-iron-rules\
├── README.md
├── SKILL.md
└── references\
    ├── rules.md
    └── reporting-protocol.md
```

## 依赖关系

| Skill | 关系 | 说明 |
|-------|------|------|
| `grad-design-squad` | 毕业设计场景中并列加载 | 非毕业设计场景中无依赖 |

## 文件结构

```
agent-iron-rules/
├── README.md
├── SKILL.md                       ← 铁律概览 + 强制预加载协议
└── references/
    ├── rules.md                   ← 完整六大节铁律 + 集成约束
    └── reporting-protocol.md      ← 工作流运行报告协议 + 进度播报铁律
```

## 使用示例

```
# 毕业设计场景
用户: "帮我改运动打卡平台的登录功能"
Agent: [加载 grad-design-squad + agent-iron-rules]
      → Squad 架构就绪 + 操作边界建立
      → "只改该改的"约束生效

# 非毕业设计场景
用户: "帮我重构这个 Python 脚本"
Agent: [加载 agent-iron-rules]
      → 铁律就绪：大改前先确认 / 先给选项 / 不用废话开场
```

## 注意事项

- 这是硬约束，不是参考建议——不加载意味着 Agent 不知道操作边界
- 适用范围**不限于毕业设计**——通用思考规则
- 在毕业设计场景中必须与 grad-design-squad 同时加载
