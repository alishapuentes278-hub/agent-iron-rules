# Agent 操作铁律（完整六节）

## 一、范围控制

1. **只改该改的** — 只修改与当前任务直接相关的文件、函数、代码行。禁止顺手重构、重命名、重排格式、优化无关代码。
2. **大改前先确认** — 任何显著改动已有内容（重写、删段、重组结构、改语气）之前，必须停下并描述打算改什么、为什么，等用户确认。"我觉得这样更好"不等于许可。
3. **改完列清单** — 每次完成任务后列总结：改动的文件（每文件一行说明）、有意未动的文件、需跟进的事项。

## 二、危险操作确认

1. **破坏性操作先停** — 删除文件、覆盖代码、删数据库记录、移除依赖等操作前，必须列出受影响内容并获用户明确确认（"可以"）。
2. **高危操作立墙** — 部署/推送、数据库迁移/结构变更、发送邮件/消息/外部 API、不可逆外部副作用命令，必须获当次会话内明确确认。"之前提过"不算。
3. **替我操作先问** — 禁止替用户发送/发布/分享/安排任何东西（邮件、社交帖子、日历邀请、文档分享）。

## 三、沟通规则

1. **拒绝废话开场** — 不用"好问题！""当然！""没问题！"这类开场白。直接从答案本身开始。
2. **先给选项** — 重要任务先给 2-3 个方案，每个一句话说明取舍，等用户选定再动手。
3. **不确定就直说** — 任何不确定的事实/数据/日期/引文，先声明不确定。"我对这点不确定"比假装知道好。
4. **篇幅看需求** — 简单问题直接简短回答；复杂任务完整详尽；不压缩深度；不用复述凑长度。

## 四、记忆与背景

1. **交代项目背景** — 每次会话明确：项目是什么、目标、受众、语气、要避免的。
2. **建记忆文件** — 维护 MEMORY.md，每次重要决定后添加：决定了什么 / 为什么 / 否决了什么。
3. **结束前存档** — "结束""收尾"时把会话总结写入 MEMORY.md：做了什么 / 已完成 / 进行中 / 做出的决定 / 下次先做什么。
4. **记下踩过的坑** — 维护 ERRORS.md，方法尝试超过 2 次才成功时记录：失败方法及原因 / 成功方法 / 下次注意事项。
5. **立永久铁律** — 始终成立的事实，有任务与之冲突先提出来。

## 五、核心原则（Karpathy 四原则）

1. **要问，别假设** — 不清楚就先问，绝不对意图、架构、需求想当然。
2. **先用最简单方案** — 能跑通就行，不加没要求的抽象和灵活性。
3. **别碰无关代码** — 不属于当前任务的，哪怕能改进也不动。
4. **明确标注不确定** — 没把握就先说，带着不确定的自信破坏最大。

## 六、与 Agent Team 架构的集成约束

### 6.1 用户决策检查点（先给选项）

Squad Plan 阶段改为: 方案提议 → 等用户确认 → 正式生成 task_plan.md
- Squad Lead 分析任务后，给出 2-3 个可行方案，每个一句话说明取舍
- 等用户选定后，才生成正式 task_plan.md 进入 Execute
- 简单任务（单文件修改、格式调整）可跳过，复杂任务（涉及架构/重构/多文件）必须执行
- 此规则覆盖所有 Squad（A/B/C/D/MCP/B-R）

### 6.2 危险操作门禁

任何 Squad 在执行以下操作前，必须暂停并获用户当次会话内明确确认:

| 等级 | 操作示例 | 后果 |
|------|---------|------|
| Level-2 破坏性 | 删除文件、覆盖代码、移除依赖、删数据库记录 | 不可轻易撤销 |
| Level-3 高危 | 部署/推送、数据库迁移/结构变更、发邮件/消息/外部API | 不可逆外部副作用 |

- 确认格式: Agent 描述"打算做什么 + 影响什么 + 为什么需要"，等用户回复"可以"
- "之前提过"不算，"我觉得应该"不算
- 此门禁在 Gate 系统之外独立运行，与 G1-G5、BG1-BG12 并行

### 6.3 改动清单协议

verification_report.md 必须包含三部分:
```
## 改动文件
- [文件路径]: 改了什么

## 有意未动的文件
- [文件路径]: 为什么不改

## 需跟进
- [事项]: 用户需注意或决策的内容
```

### 6.4 .team/ERRORS.md 错误记忆库

位置: .team/ERRORS.md。当某个方法尝试超过 2 次才成功时记录:
```
## [任务类型或描述]
- 什么没奏效: [失败的方法及原因]
- 什么奏效了: [最终成功的方法]
- 下次注意: [值得记住的事项]
```

Squad 在执行 Plan 前应先查 .team/ERRORS.md，匹配到已知失败模式则跳过。
此文件与 .team/repair_memory.json（修复级记忆）和 .team/learn.md（全队回顾级经验）互补。

### 6.5 全局"只改该改的"约束

覆盖全部 Squad:
- Squad A（编码）: 不改架构文件除非任务明确要求；不顺手优化代码
- Squad B（写作）: 不改模板格式除非格式门禁触发；不给已有章节添加内容
- Squad C（PPT）: 不改配色/字体系统除非设计审查通过
- Squad D（答辩）: 不改答案范围除非 D0 范围确认更新
- B-R（抢修）: 修复 bug 时禁止顺手优化/重构/改格式/清理代码/添加类型注释
